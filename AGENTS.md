# AGENTS.md — AKG ALGO

Briefing for coding agents. This file is deliberately short. Detail lives in `docs/` and `plans/`; open those files when the task needs them.

## What this project is
A self-hosted membership website for a trading business: monthly **signal subscriptions** (dashboard), **MT4/MT5 bot sales** (license keys), a **Connector demo**, an **admin panel**, and an **admin-only broadcast feed**. Payments are mostly **USDT**. Two roles: `user`, `admin`.

1. `docs/00-PRODUCT.md` — scope and what is out of scope
2. `docs/02-BUSINESS-RULES.md` — cycles, access, signals, broadcast, bots (the rules that matter most)
3. `plans/PLANS.md`, then the current phase file in `plans/` — your task list

## Commands (script names are fixed in Phase 0; keep them stable)
- `pnpm install` — install
- `pnpm dev` — web app on http://localhost:3000
- `pnpm dev:worker` — background worker
- `pnpm typecheck` · `pnpm lint` · `pnpm test` · `pnpm test:e2e` — all must pass before you finish a task
- `pnpm db:generate` — create a migration from schema changes
- `pnpm db:migrate` — apply migrations
- `pnpm db:seed` — load demo data (see `docs/07-TESTING.md`)
- `docker compose up -d db` — local Postgres; `docker compose up --build` — full stack

## Layout
```
apps/web        Next.js app (user panel + admin panel)
apps/worker     background jobs (pg-boss)
packages/core   business rules as pure, tested functions  <- access control lives here
packages/db     Drizzle schema, migrations, seed

```

## Rules that never bend
1. **Authorization is server-side**, on every route/action: session + role + entitlement. Hiding UI is not security.
2. **One access function** (`hasSignalAccess` in `packages/core`) decides who sees signals. Never re-implement it elsewhere.
3. Payment confirmation runs in **one DB transaction** and is **idempotent**.
4. **Never log or return secrets**: passwords, trading-account credentials, license secrets, wallet keys.
5. Validate every input with Zod at the server boundary.
6. Timestamps in UTC; cycle dates use the admin-set business timezone.
7. Every admin write creates an `audit_log` row.
8. User-supplied or admin-supplied text is rendered as plain text or sanitised Markdown — never raw HTML.
9. The Connector never connects to a broker (demo only). `CONNECTOR_REAL_MODE` stays `false`.
10. No fake statistics, testimonials, or invented performance claims anywhere in the UI.

## Conventions
- TypeScript strict; no `any` without a one-line reason. Named exports; small files; business logic in `packages/core`, routes stay thin.
- Money = integer minor units + currency code. Never floats.
- Schema changes only through Drizzle migrations; never edit applied migrations.
- Auth tables are generated by the Better Auth CLI; do not hand-edit generated auth schema.
- Use the existing logger (pino), not `console.log`. Use the existing UI components (shadcn/ui) before writing new ones.
- Use only dependencies approved in `docs/08-DEPENDENCIES.md`. Add a new one only with a line in `docs/DECISIONS.md`.

## Working method
1. Open the current phase file; pick the next unchecked task.
2. Write or update the test first for anything in `packages/core`.
3. Make the smallest change that completes the task.
4. Run `pnpm typecheck && pnpm lint && pnpm test`; run `pnpm test:e2e` when a user flow changed.
5. Tick the task in the plan, add one line to its Progress Log, commit with a clear message.

## Gotchas
- Next.js 16 uses `proxy.ts` (formerly `middleware.ts`).
- Check current library docs before using an API; do not rely on memory for versions or signatures.
- pg-boss current API: `createQueue`, `send`, `work` (the handler receives an array of jobs). Use `timgit/pg-boss`, not old forks.

## When something is unclear
Apply the default in `docs/DECISIONS.md`, record what you assumed, and continue. Stop and ask only for items marked **BLOCKING**.

## Definition of done (per task)
Typecheck, lint, tests pass · behaviour matches `02-BUSINESS-RULES` · authorization verified by a test · migration included if the schema changed · plan ticked and logged.
